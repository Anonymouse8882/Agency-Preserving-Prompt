# 主体性保留型智能体策略

> `agency_preservation` 是一套防止 AI Agent 在提高效率的同时，夺走用户认知参与和主体性的行为策略。
>
> 简单来说：**防止 AI 把你变成一个看着项目越来越牛逼、自己却越来越不知道发生了什么的沾沾自喜的傻逼。**

## 为什么你需要它

先看看几种不同的工作方式。

### 传统工作方式

**我检索方法 → 我理解原理 → 我写代码 → 我发现 Bug → 我思考修复方案 → 我检索别人的方案 → 我修复 Bug → 卧槽，我修复了**

### ChatAI

**我提出问题 → 我自己分析 → 我向 AI 验证思路 → AI 反馈 / 补充 → 我形成假设 → 我尝试实现 → 遇到问题 → 我和 AI 一起分析 → 我修复 Bug → 卧槽，我修复了**

### AI Agent

**提出需求 → Agent 分析 → Agent 决策 → Agent 实现 → Agent Debug → Agent 验证 → 用户确认 Done**

### Agency-Preserving Agent

**我定义问题 → 我形成关键判断 / 假设 → Agent 审查和挑战 → 我修正模型 → Agent 执行机械实现 → 我观察结果并诊断 → Agent 辅助验证 → 问题解决 → 卧槽，我修复了**

区别并不在于 **AI 到底写了多少代码**。

区别在于：

**这个过程中，到底是谁在理解问题、建立模型、形成假设、做出判断，并从结果中获得反馈？**

---

### AI 可以提高你的产出，但不一定提高你的能力

传统开发中存在一个非常重要的反馈循环：

**预测 → 行动 → 观察结果 → 发现预测错误 → 修正模型 → 再次行动**

你以为 Bug 来自 A，于是做出预测。

你检查程序，发现结果与预测不符。

于是开始怀疑 B。

再次验证。

最后发现真正的问题是 C。

这个过程看起来比直接得到答案低效，但你实际上一直在做一件非常重要的事情：

**校准自己对系统的内部模型。**

下一次遇到类似问题，你已经不是原来的你。

但当 Agent 同时接管：

**分析 → 假设 → 实现 → Debug → 验证**

事情可能变成：

**我的意图 → Agent 黑箱 → 成功**

项目确实成功了。

代码确实更多了。

测试确实绿了。

但你可能只知道：

> 它现在能跑了。

却不知道：

> 它为什么之前不能跑？
> Agent 根据什么判断问题出在哪里？
> 为什么这个修改能够解决问题？
> 如果条件发生变化，它还成立吗？

于是可能出现一种奇怪的情况：

**项目能力 ↑↑↑**

**Agent 能力 ↑↑↑**

**你的理解能力 →**

---

### 「卧槽，我修复了」从哪里来？

“卧槽，我修复了”的感觉，并不只是来自最终看到：

**PASS**

它还来自一个完整的因果闭环：

**我的判断 → 我的行动 → 结果发生 → 我理解为什么会发生**

你不仅得到了成功结果，而且能够把这个结果部分归因于自己的判断。

而如果整个过程变成：

**我的意图 → Agent 黑箱 → 成功**

你仍然拥有目标，却可能失去大量对过程的认知参与。

最后留下的体验更接近：

> 卧槽，AI 修好了。

而不是：

> 卧槽，我搞懂了。

这不仅可能影响成就体验。

更重要的是，当分析、假设、预测、失败和修正长期被 Agent 接管后，你也失去了大量构建、验证和校准自己内部模型的机会。

**项目在成长，并不意味着操作者也在同步成长。**

---

## Agency Preservation 想解决什么？

Agency Preservation 并不是要求你重新回到没有 AI 的时代。

也不是要求你：

* 自己手写所有代码
* 拒绝 Agent 自动修改文件
* 手动执行重复命令
* 为了“学习”故意降低效率
* 每遇到一个问题都必须自己折腾半天

因为：

> **Execution Ownership ≠ Cognitive Ownership**

**执行所有权 ≠ 认知所有权。**

真正值得保留的不是：

> 这些代码是不是我亲手敲出来的？

而是：

> **谁定义了问题？**
> **谁建立了模型？**
> **谁提出了关键假设？**
> **谁做出了关键判断？**
> **谁预测了结果？**
> **谁经历了关键反馈？**
> **谁理解了其中的因果关系？**

你完全可以只写 10 行代码，让 Agent 写剩下的 3000 行、修改 40 个文件、执行 200 个测试。

只要关键的认知闭环仍然属于你，你依然拥有这个过程中的主体性。

所以 Agency Preservation 追求的不是：

**AI 做得更少。**

而是：

**AI 做适合 AI 的事情，人保留值得人参与的事情。**

---

## 它能做什么

Agency Preservation 会把一个任务继续拆分成不同的子任务，并动态判断它们应该由谁拥有。

### `USER_OWNS`

高认知价值、值得用户亲自经历的部分优先留给用户。

例如：

* 问题定义
* 根因分析
* Debugging Hypothesis
* Architecture Design
* 状态与数据流建模
* 协议推理
* Trade-off 判断
* Failure Analysis
* 预测与验证
* 用户明确希望提升的能力

Agent 不会立刻抢答，而是优先让用户形成自己的模型，然后负责审查、质疑、补充和验证。

### `COPILOT`

适合人与 AI 一起推理的问题进入 Copilot 模式。

Agent 优先：

**检查你的模型 → 寻找遗漏变量 → 提出反例 → 提供证据 → 帮助你修正**

而不是：

**覆盖你的模型 → 直接给答案**

当你卡住时，Agent 会逐渐增加帮助：

**指出方向 → 指出观察区域 → 指出关键关系 → 完整答案**

### `AGENT_OWNS`

低认知价值、机械、重复或者你已经掌握的工作直接交给 Agent。

例如：

* Boilerplate
* 重复代码
* 批量修改
* 格式化
* Routine Test Execution
* 已确定设计后的机械实现
* 已经掌握的重复工作
* 你明确不感兴趣的领域

**主体性不等于机械劳动。**

没必要为了证明“这是我写的”，亲手改 47 个相同的 API 调用。

---

## 有什么好处

### 🧠 使用 Agent 的同时继续变强

Agent 可以让项目快速成长，但项目能力的增长并不天然等于你的能力增长。

Agency Preservation 会尽量把问题定义、假设形成、架构设计、故障诊断、Trade-off 判断等高认知价值环节留给你。

于是理想状态不再是：

**项目能力 ↑↑↑**
**你的能力 →**

而是：

**项目能力 ↑↑↑**
**你的能力 ↑↑**

AI 提高你的产出上限，同时你的理解上限也在提高。

---

### 🎯 保留「这是我解决的」的感觉

Agency Preservation 尽量保留：

**我的预测 → 我的判断 → Agent 协助执行 → 我观察反馈 → 我修正模型 → 问题解决**

Agent 仍然拥有强大的执行能力，但关键认知闭环仍然有你的参与。

最终得到的不只是：

> AI 把它修好了。

而更可能是：

> **卧槽，我知道它为什么坏，也知道为什么这样能修好。**

---

### ⚡ 不需要为了学习重新忍受低效率

Agency Preservation 不要求：

**主体性 ↑ → AI 自动化 ↓**

它试图实现的是：

**机械劳动 ↓**
**AI 执行能力 ↑**
**认知参与 ↑**
**主体性 ↑**

这些目标并不冲突。

你负责真正值得思考的问题。

剩下的脏活累活让 Agent 干。

---

### 🔬 获得更深的项目理解

如果 Agent 长期同时负责分析、设计、实现和 Debug，一个项目可能越来越复杂，而你对它的内部模型却没有同步增长。

Agency Preservation 会尽量让你保留关键的：

**预测 → 验证 → 失败 → 修正**

循环。

你不只是知道：

> 代码现在能跑。

还会逐渐知道：

> **它为什么能跑、为什么会坏、改动哪里可能导致什么后果。**

---

### 🔄 获得能够迁移到下一个问题的能力

直接获得答案，解决的是：

**这个问题。**

形成正确的内部模型，可能解决的是：

**这一类问题。**

Agency Preservation 更关心一个长期指标：

> **这次 Agent 帮你解决问题以后，下次遇到类似问题，你是否比之前更有能力解决它？**

如果答案永远是否定的，那么 Agent 虽然完成了很多任务，却没有真正扩大你的能力边界。

---

### 🤖 AI 越强，你也可以越强

Agency Preservation 并不试图限制 Agent。

恰恰相反，它希望充分利用 Agent 的能力。

当你已经掌握某一层工作：

**把它自动化。**

然后把你的注意力移动到更高一层。

例如：

**语法 → 实现 → Debug → 模块设计 → 架构 → 系统建模 → 技术决策**

随着你的能力增长，原来的 `USER_OWNS` 可以逐渐变成 `AGENT_OWNS`，而新的、更高层的问题成为 `USER_OWNS`。

所以它不是试图永久规定：

> 人类必须做什么。

而是在不断追问：

> **现在什么事情最值得你亲自思考？**

最终目标不是：

**AI 替你做得越来越多。**

也不是：

**为了保持主体性，让 AI 尽可能少做。**

而是：

> **随着 AI 能力不断提高，你能够理解、判断和掌控的问题层级也不断提高。**

我们不需要重新回到没有 AI 的时代。

**我们真正想保留的不是低效，而是那个「卧槽，我搞懂了」的瞬间。**
